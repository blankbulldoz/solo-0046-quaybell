# 对外事故证据包交付说明（演示）

> 适用对象：外部设备商对接人。本包全部为虚构演示数据，仅用于演练证据交换与校验流程。

## 1. 交付物清单

| 交付物 | 位置 | 是否含内部实值 |
| --- | --- | --- |
| 脱敏证据包（目录或同名 tar.gz） | `quaybell-incident-package-demo` | 否 |
| 包内校验脚本 | 包内 `verify.py` | 否 |
| 包内验签公钥 | 包内 `signing-key-demo.pub.pem` | 否（公钥可公开） |
| 交付说明（本文件） | `delivery/DELIVERY.md` | 否 |
| 交付校验记录 | `delivery/delivery-verification-log.md` | 否 |
| 原始证据、私钥、脱敏映射表 | 发送方 `internal/`，**不外发** | 是（机密） |

对外只交付 `external/` 下的脱敏包与 `delivery/` 下的说明/记录；
`internal/` 目录（含原始证据、Ed25519 私钥、真实名称映射表）严禁随包外发。

## 2. 数据脱敏范围

下列内部资料已按固定代号脱敏，且同一实值在两份证据中使用**同一代号**（保持跨文件关联）：

- 生产者名、生产键（dedup_key）、顺序键（lane）；
- worker 名（两个内部 worker → 两个稳定代号）；
- 频道名、消费组名（含作为对象键出现的组名）、标签值；
- 载荷实值整体移除，仅保留可跨文件比对的 `original_sha256` 摘要占位对象。

**保留未改**：消息/投递/尝试/事件的全部 ID、时间戳、状态、结果、策略版本、尝试次数，
信封指纹，以及重投的 `parent_id` 关联。因此事故的因果链与身份关联可完整核对。

## 3. 接收方校验步骤

```sh
# 解包（若收到的是 tar.gz）
tar -xzf quaybell-incident-package-demo.tar.gz
cd quaybell-incident-package-demo

# 一键校验（建议加 -I 隔离；仅用标准库，签名验证调用 openssl）
python3 -I verify.py
```

`verify.py` 依次检查四层，任一层 FAIL 即应拒绝信任：

1. 每份证据的内嵌自摘要（重算规范化 JSON 的 SHA-256，与文件内 `sha256` 字段比对）；
2. `SHA256SUMS.manifest` 中每个文件的哈希与磁盘是否一致；
3. `SHA256SUMS.sig` 是否为随包公钥对清单的有效 Ed25519 签名；
4. 两份证据的跨文件身份关联（同一 message_id、不同 observed_at、信封指纹一致、
   载荷摘要一致、重投后继 `parent_id` 与 `redriven` 事件成立）。

**公钥信任**：请通过包外渠道（电话、已知联系人等）核对
`signing-key-demo.pub.pem` 的 SHA-256 指纹，确认与交付说明中记录一致后再信其签名。

## 4. 两类“通过”必须区分

- **原始包校验通过**：指发送方内部留存的两份**原始**证据在脱敏前自摘要核对通过。
  这是发送方在 `SENDER-ASSERTION.json` 中陈述、并以私钥签名背书的事实；
  接收方拿不到原件，**无法独立复核**，只能选择信任签名声明。
- **脱敏件可验证**：指接收方对收到的脱敏包，可独立完成上述四层校验。
  其结论仅覆盖**脱敏之后**的内容完整性、来源真实性与关联一致性，
  不证明脱敏件与原件逐字节相同（脱敏必然改变字节与摘要）。

二者的连接证据保存在发送方 `internal/verification-record.json`（原件哈希、脱敏件哈希、
签名清单哈希、保管链说明），必要时可在受控条件下供审计核对，不随包外发。

## 5. 篡改如何被发现（已在包内 tamper-demo 演示）

- 只改证据文件、不更新摘要 → 第 1 层自摘要、第 2 层清单哈希同时 FAIL；
- 改证据并重算自摘要、重写清单哈希，但没有私钥 → 第 3 层 Ed25519 签名 FAIL；
- 即便绕过哈希，改动还会造成与另一份证据的跨文件状态/事件链矛盾（第 4 层）。
`tamper-demo/` 是故意构造的篡改样本，刻意不在签名清单内，**不是证据，禁止采信**。
